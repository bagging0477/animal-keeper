박쥐 몬스터 — 실제 32×32 픽셀 원본

1. 구성
Frames/: 상태별 개별 PNG 16장. 전부 실제 32×32, RGBA 투명 배경.
bat-monster-atlas.png: 128×128, 4열×4행, 32×32로 분할 가능.
shadow.png: 그림자만 분리한 16×4 PNG. 단색 #534545.
validation.json: 각 프레임의 크기, 사용 색 수, 불투명 영역 기록.
확대 시안을 바탕으로 원본 크기와 팔레트를 정리했습니다.
각 프레임의 불투명 색상은 최대 8색이며, 외곽선 색은 #2F2F2E입니다.
첨부 원본 동물과 같은 크기로 보이는지는 실제 게임에서 마지막으로 비교해 주세요.
몸의 길이는 자세/날개에 따라 달라지며 몸과 날개를 합친 폭은 대체로 18~22도트 범위입니다.
일부 원근/날개 자세는 작은 프레임에서 실루엣을 우선했습니다.

2. 애니메이션 목록
fly-01 ~ fly-06: 비행, 10~12 fps, Loop 켜기.
freeze-01: 굳음, 정지 1장.
bite-01 ~ bite-04: 물기 공격, 10~12 fps, Loop 끄기.
wrap-01 ~ wrap-03: 날개를 접어 웅크리기, 6~8 fps, Loop 끄기. 마지막 프레임 유지.
hurt-01: 피격/기절 예비 포즈 1장.
fallen-01: 쓰러짐 예비 포즈 1장.
피격과 사망이 실제 게임에 필요한지는 확인되지 않았으므로 예비로만 포함했습니다.
별도 등장 동작은 만들지 않았습니다.
아틀라스 순서: 맨 위 왼쪽부터 오른쪽, 그다음 줄 순서입니다.
1~6 비행, 7 굳음, 8~11 물기, 12~14 웅크림, 15 피격, 16 쓰러짐.
좌우반전은 SpriteRenderer의 Flip X를 사용하세요. 기본 방향은 오른쪽입니다.

3. PNG 가져오기
압축을 풀어 원하는 폴더를 Unity Assets 안으로 드래그하세요.
개별 Frames PNG를 쓴다면:
Texture Type = Sprite (2D and UI)
Sprite Mode = Single
Pixels Per Unit = 32 (박쥐 배율 2 기준)
Filter Mode = Point (no filter)
Compression = None
Generate Mip Maps = Off
Pivot = Center (0.5, 0.5)
Apply를 누르세요.
Scale (2,2,1)이면 1원본 픽셀 = 2/32 = 월드 1/16입니다.
Scale (1,1,1)로 쓰려면 PPU 16으로 바꾸세요.
일반 공식 PPU = 16 × 실제 최종 오브젝트 배율. 부모 배율도 포함해야 합니다.
1080p에서 약6px로 보일지는 현재 게임 카메라 설정도 함께 확인해야 합니다.
비정수 화면 배율이나 서브픽셀 위치에서는 도트 간격이 흔들릴 수 있습니다.

4. 아틀라스로 쓰기 (개별 PNG 방식과 둘 중 하나만 선택)
128×128 아틀라스의 Sprite Mode를 Multiple로 지정합니다.
Sprite Editor > Slice > Grid By Cell Size > Pixel Size X32 Y32로 분할합니다.
Pivot Center, Apply.
나뉜 Sprite를 상태별로 골라 Animation 클립을 만드세요.
분할 도구는 프로젝트에 2D Sprite 패키지가 필요할 수 있습니다.

5. 클립 만들기
예를 들어 fly-01~06을 이름순으로 선택해 Scene으로 드래그하면 클립 생성 창이 열립니다.
저장 후 Animation 창에서 Samples를 10 또는 12로 맞추세요.
비행 클립의 Loop Time을 켜세요.
물기/웅크림은 별도 클립을 만들고 Loop Time을 끄세요.
이미 존재하는 몬스터에는 기존 SpriteRenderer/Animator에 클립을 연결하세요.
이 세트에는 게임의 실제 Animator Controller나 행동 AI 스크립트는 포함하지 않았습니다.

6. 우는천사 동작 연결 기준
보지 않을 때: 이동 로직 활성화 + 비행 루프.
볼 때: 이동 로직 정지 + freeze-01 또는 비행 현재 프레임 정지 중 하나를 선택.
비행 현재 프레임 정지를 택하면 animator.speed=0으로 멈추고 다시 움직일 때 1로 복구합니다.
별도 굳음 상태로 전환한다면 Animator가 새 상태를 평가해야 하므로 전환 전에 speed를 0으로 막지 마세요.
포즈 정지와 실제 이동 정지는 별개이므로 이동 AI도 함께 멈춰야 합니다.
공격 판정은 이미지가 아닌 기존 게임 공격 코드와 맞추세요.
실제 우는천사 상태 목록/전환 조건을 확인한 뒤 연결해야 합니다.

7. 그림자 — 이미지에 포함하지 않음
BatRoot 아래에 Shadow와 BatVisual을 별도 자식으로 두는 구성을 권장합니다.
Shadow는 바닥 위치에 고정하고 BatVisual만 비행 높이/상하 흔들림을 적용하세요.
날갯짓이나 부유에 맞춰 Shadow를 위아래로 이동시키지 마세요.
Shadow 색은 PNG 자체에 #534545가 들어 있으므로 SpriteRenderer Color는 흰색으로 두세요.
그림자 폭은 날개 폭이 아니라 실제 몸 폭 × 0.75에 맞게 조절하세요.
그림자 원본의 PPU/Scale은 그림자의 도트 크기 기준도 유지하도록 정하고, 필요하면 원본 폭을 수정하세요.
정렬 순서는 바닥 < 그림자 < 박쥐로 설정하세요.
발 기준 피벗은 변경하지 않았습니다.

8. 아트 확인 / 한계
시안과 달리 내려받는 Frames PNG는 실제32×32입니다.
팔레트와 해상도, 프레임별 투명 배경, ZIP은 검사했습니다.
아트가 손으로 그려졌다고 주장하지 않습니다. 생성 기반 초안을 원본 해상도로 정리한 세트입니다.
다른 작가의 그림과 완전히 동일한 스타일이라고 보장할 수 없습니다.
게임 내 원본 늑대와 1:1 화면 비교, 공격 판정 및 실제 상태 연결, Unity Play 테스트는 하지 못했습니다.
가장 중요한 최종 확인: 동일한 카메라/배율로 늑대와 나란히 배치해 한 도트가 같은 화면 크기인지 확인하세요.
